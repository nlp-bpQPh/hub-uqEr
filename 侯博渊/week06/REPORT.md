# 换预训练模型实验：StructBERT-tiny vs BERT-base / TF-IDF / 规则

> 数据集不变（CLUE TNEWS，15 类）；评测集不变（去重后 500 条干净验证样本，seed=42）。

> 目的：在**无 GPU** 的机器上回答「把 102M 的 BERT-base 换成 8.8M 的小模型，会掉多少点、省多少成本」。

## 结论速览

- **15 类**：小模型 0.4815，BERT 0.5436（-6.2 点），TF-IDF+SGD 0.5167。
- **业务口径**：4 组 0.7100 vs 0.7060，相关性 F1 0.8114 vs 0.8154——几乎打平。
- **成本**：8.8M / 35MB，CPU 约 65 分钟；BERT 102.3M / 390MB，GPU 约 14 分钟（硬件不同，时间不可直接比）。

## 五、分析

1. **小模型 vs BERT-base**：8.77M vs 102.3M（约 1/12 参数），15 类 Macro-F1 0.4815 vs 0.5436，差 **-6.2 个点**。注意训练时间不能直接比：小模型 3932s 是 **CPU**，BERT 828s 是 **GPU**。
2. **小模型 vs TF-IDF+SGD**：0.4815 vs 0.5167，差 **-3.5 个点**。TF-IDF 只要 8 秒，小模型要 3932 秒——**这个任务上线性模型仍然更划算**。
3. **换成业务口径，差距几乎消失**：4 组主题准确率 0.7100 vs BERT 0.7060，相关性 F1 0.8114 vs 0.8154。15 类那 6.2 点差距主要来自**细分边界**，大类判断/相关性几乎不输——如果产品只用 4 组 + 相关性，8.8M 小模型就够。
4. **per-class 看能力分配**：小模型在 故事 0.85 vs BERT 0.46、证券 0.60 vs 0.40、房产 0.56 vs 0.38 更好；但 财经 0.38 vs 0.54、科技 0.37 vs 0.50、国际 0.32 vs 0.59 更差——不是全面退化，而是把容量偏向了长尾/易混类。
5. **置信度**：小模型 ECE 0.1255，BERT 0.1418；两者都偏自信（>0.1），服务里仍需温度校准，不能直接拿 0.8 当阈值。
6. **对项目的含义**：本项目「数据封闭 + 短文本 + 15 个粗类」的特点是：TF-IDF 已经能拿到 0.5167，BERT-base 0.5436，小模型 0.4815；但到 4 组/相关性口径，小模型与 BERT 几乎打平。选型不是「越大越好」，而是「业务需要多细的标签 + 延迟/成本能接受多少」。
7. **可复现性**：新模型权重在 `_models/structbert-tiny/`，训练与评测脚本在 `experiments/`，数据与指标复用 `code/common/` 的同一套口径；BERT-base 一行是项目现成结果，未重训（本机无 GPU）。

## 六、局限

- 小模型只训了 3 epoch、lr 5e-5，没有做超参搜索；换 lr / 更长训练可能再涨 1–2 个点。
- 500 条评测样本的统计噪声约 ±2 个点，1–2 个点的差异不能当结论。
- BERT-base 是项目里 GPU 上跑的结果，训练耗时 828s 来自 `bert_train_log.json`。
- 没有跑 LoRA / 全量微调 / API zero-shot：本机无 GPU 或需要 key，它们在同口径下的结果见 `code/outputs/summary.md`。
