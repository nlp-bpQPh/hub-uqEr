流程：
    language_model.py   →  Decoder 思路：因果掩码 + 下一个字预测（GPT 的原理）
    pinyin_ime.py       →  模型只是"打分器"，产品 = 约束搜索空间 + 束搜索解码
    bert/diy_bert.py    →  Encoder 思路：双向注意力 + 预训练权重直接拿来用

三个部件在解决什么：
    因果掩码    位置 i 只能看 ≤i 的字；因为一次前向就把整句话的"下一个字"全算出来了，
                所以一条 128 字的样本 = 128 个训练样本，训练信号 100% 利用
    位置编码    attention 本身不知道先后，正弦编码把"第几个字"塞进向量
    权重绑定    输出层和 Embedding 共用同一块 4000×128 矩阵（省一份参数，也起正则作用）
    束搜索      模型只负责给概率；怎么选字是搜索策略的事（贪心 / top-k / top-p / beam）

调参：
    参数	        说明
1	lr + 调度	3e-4 是小 Transformer 的甜点；大模型更小（1e-4 ~ 1e-5）。先确认 warmup 在生效（打印 lr 曲线）
2	seq_len	    上下文长度的取舍：长 = 见识远但显存/时间按平方涨。128→256 先看 val PPL 是否还降
3	模型尺寸	d_model 128、ffn 256。经验比例 ffn ≈ 4×d_model（这里只有 2×，加大到 512 值得一试）；nhead 通常 4~8，必须整除 d_model
4	dropout	    小语料必开（0.1 起步）；语料 >> 模型容量时可降到 0
5	num_layers	加深比加宽收益大，但 2 层小模型加深后 lr/warmup 要跟着调
6	max_vocab	4000 字对中文够用；生僻字被 <UNK> 吞掉会伤 PPL，看字频长尾再定
7	stride	    切块间隔。0（=seq_len）不重叠，样本数 = 字数/128；改成 1 会让样本数暴涨 128 倍，
                一轮训练慢 100 倍以上，而 Transformer 每个位置本来就能并行看全段，重叠几乎不带来新信息

PPL（困惑度）：
    困惑度越低，模型越好。
    PPL = exp(平均交叉熵)，可以理解成"预测下一个字时，平均在多少个字里犹豫"：
    PPL 133 ≈ 每次在 133 个候选字里挑；PPL 40 ≈ 40 个里挑。它和 loss 是一回事，只是换了个刻度。

训练时盯着三个信号：
    现象                                    诊断                          动作
    PPL 比 2-gram 还高，且 train≈val         欠拟合（步数/容量不够）       加 epochs、减小 stride、减小 batch；先把 PPL 压到远低于 2-gram 再谈调结构
    train PPL 一路降、val PPL 先降后升       过拟合                        加 dropout、加语料、减层数、早停
    生成的文本全是重复换行/句号              采样策略 + 模型没训好         先看 PPL；再用 T / top-p 调，别用贪心
    warmup 期间 loss 反而往上走              lr 峰值太高或 warmup 太短     打印 lr 曲线确认，warmup 比例 5% → 10%
    一轮训练特别慢                            stride=1 把样本数放大了 128 倍 用 stride = seq_len（不重叠切块）

实测（作业/best_model.pt，复算脚本 作业/eval_ppl.py，切分与训练完全一致）：
    训练配置       语料前 2,000,000 字 → 字表 4000；seq_len 128、stride 128、batch 256；
                   d_model 128 / ffn 256 / 2 层 / 4 头 / dropout 0.1；
                   AdamW lr 3e-4、warmup 5%、权重衰减 0.01、梯度裁剪 1.0；3 轮；参数 1,293,216
    训练量         每轮只有 57 个 batch，3 轮合计 171 步 —— 这个数字是关键
    验证集（100,482 字）  loss 6.3587  PPL 577.51
    训练集（前 200 batch）loss 6.3630  PPL 580.01
                   → train 和 val 几乎一样，说明不是过拟合，是根本没学起来
    同一划分的统计模型对照
        1-gram   PPL 538.65
        2-gram   PPL 133.29   ← 比我们的 Transformer 好 4 倍
        3-gram   PPL 477.69   ← 反而变差：数据稀疏，三字组合大多没在训练集出现过
    结论：这个 checkpoint 只能算"流程跑通了"，不能当语言模型用。
          2-gram 都打不过，说明问题在训练量（171 步）而不是结构；
          下一步先加步数（epochs 3→15，或 stride 128→32 把每轮 batch 数拉上去），
          再看 PPL 能不能压到 2-gram 以下，那时再谈调 d_model / ffn / seq_len 才有意义。
          （作为参照，课堂 tools/lm_stats.json 里用 602 万字语料算的 LSTM PPL 是 38.32、RNN 40.83，
           口径不同不能直接比，但量级差距说明：同结构下训练量差一个数量级，PPL 就差一个数量级。）
