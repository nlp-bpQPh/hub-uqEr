## 二、数字字典（看不懂哪个数就查这里）

### 三个核心指标（都越高越好，满分 1）

| 指标 | 含义 | 怎么算 | 为什么重要 |
|---|---|---|---|
| `trigger F1` | "发生了什么"找得准不准 | 触发词 span 与金标完全一致才算对 | 事件识别第一步，低了后面全废 |
| `argument F1` | "涉及哪些要素"填得准不准 | 论元 span + 角色名都对才算对 | **最关键**，也是各方法差距最大的地方 |
| `event_exact F1` | 整个事件完全正确的比例 | 类型 + 全部论元 + 边界全对才计数 | 最严格，业务上真正能用的标准 |
| `type_macro_f1` | 13 个事件类型 F1 的平均 | 每类算完再平均，不按样本数加权 | 防"大类刷分"，看稀有类型有没有学会 |

### 训练过程指标

| 指标 | 含义 | 健康值 |
|---|---|---|
| `train_loss` | 训练集损失，初始约 **5.0**（= ln149 类） | 应持续下降；停在 3.5 以上通常没学够 |
| `inner_loss` | 内层验证集（训练集里切的 10%）损失 | 应跟着降；**开始上升**=过拟合 |
| `inner_spanF1` | 内层验证集 span F1（阶段 A 80 句噪声大 / 阶段 B 574 句较稳） | 用来选"第几轮最好"，不看绝对值看趋势 |
| `dev_spanF1(监控)` | dev 上实时 F1，每轮跑一次 | 判断哪个 epoch 真有用 |
| `best_epoch` | 最终选中的轮次 | 若 = 最后轮，说明还在涨，可加 epoch |

### 结构与效率指标

| 指标 | 含义 | 说明 |
|---|---|---|
| `非法 BIO` / `illegal_seqs` | 模型输出的标签序列违反 BIO 规则（如 `O` 后接 `I-`） | linear 必然有；**CRF 只能压一部分、且不可靠**（本机 4L CRF 仍有 84.6%，见 E10） |
| `illegal_start` | 句首出现 `I-` 标签的处数 | 说明模型不懂"序列必须从头开始" |
| `illegal_transition` | 非法标签跳转处数 | 说明模型不懂标签之间的转移规则 |
| `推理延迟 ms/句` | 单句推理耗时 | 上线成本的核心指标 |
| `峰值显存 MiB` | GPU 占用，你是 CPU 所以恒为 0 | 报告里要写"纯 CPU，未使用 GPU" |
| `参数 M` | 模型参数量（百万） | 4 层约 45.7M，12 层约 102.4M |

### 三个"数据集"名字

| 名字 | 含义 |
|---|---|
| `训练 720 句 / 内验 80 句` | 阶段 A：`data/myexp`（800 句切 10%），E01~E04 |
| `训练 5173 句 / 内验 574 句` | 阶段 B：`data/processed`（5747 句切 10%），E05 起 |
| `评测 dev 930 句` | 真正用来打分的裁判集，**两个阶段用的都是同一份，所以分数可以横向比** |

> 注意：`非法序列 0 条`不一定是好事。全输出 `O` 时天然合法，这是"全 O 坍缩"的副产品；模型真在标东西时非法率反而会跳到 60% 以上。

## 三、实验记录

### 阶段 A：myexp 800 句（欠训练诊断，E01~E04）

### E01 规则基线

- **run_name**：`rule`
- **命令**：`python rule\run_rule.py`
- **配置**：词典 99 条触发词 + 3679 个公司名词典；无训练；评测 dev 930
- **结果**：trigger 0.6168 / argument 0.1740 / event_exact 0.0161 / type_macro 0.8118；1.124 ms/句
- **判断**：规则能定位触发词（六成），但论元误报 3413 处（`arg_spurious` 517 条，55.6%）。规则的天花板就在这里——**只能"发现事件"，不能"填全要素"**。
- **决策**：作为 L0 参照线保留，后续所有模型都与它对比。

### E02 BERT-4L + Linear（1 epoch）

- **run_name**：`bert4L_linear_128`
- **命令**：`python bert\train.py --data_dir data/myexp --bert_layers 4 --max_len 128 --epochs 1 --decoder linear --run_name bert4L_linear_128`
- **配置**：720 训练 / 80 内验 / 930 评测；batch 32；lr 2e-5；head_lr_mult 5.0；seed 42；**23 步**
- **结果**：train_loss 5.158 → 3.665；inner_spanF1 = 0.0000；trigger/argument/event 全 0；896/930 句无触发词；非法序列 10.8%；参数 45.7M；训练 177s；推理 40.48 ms/句
- **判断**：**接近坍缩，但还没完全塌**。77.9% 的 token 是 `O`，23 步不足以越过"全猜 O"的局部最优（train_loss 只从 5.16 降到 3.67，离收敛很远）。**注意它不是全 `O`**：触发词报了 34 个、**全错**（tp=0 / fp=34），论元报 20 个也全错，非法序列 100 句（10.75%）。到 E03/E04 才**彻底全 `O`**（fp=0、非法 0 条）——"全 `O`"是更晚一步才发生的状态。
- **决策**：**只改 epochs 1 → 3**，其余不动（单变量原则）。理由：23 步 × 3 ≈ 69 步，才接近能学出结构的量级。

### E03 BERT-4L + Linear（3 epoch，max_len 128）

- **run_name**：`bert4L_linear_128_3e`
- **命令**：`python bert\train.py --data_dir data/myexp --bert_layers 4 --max_len 128 --epochs 3 --decoder linear --run_name bert4L_linear_128_3e`
- **配置**：720 训练 / 80 内验 / 930 评测；batch 32；lr 2e-5；head_lr_mult 5.0；seed 42；**69 步**（23 步/轮 × 3）
- **结果**：train_loss 3.5902 → 1.6352 → 1.4381；inner_spanF1 三轮全 **0.0000**；`best_epoch=1`；trigger tp=0 fp=0 fn=930；argument tp=0 fp=0 fn=4122；event_exact fn=930；非法序列 0 条（全输出 O 的副产品，不算好）；总训练 526.7s（175.4 / 176.9 / 174.1）；推理 39.79 ms/句
- **与 E02 的数字差异说明**：E03 的第 1 轮末 loss（3.5902）低于 E02 的（3.665），但两者 `steps.jsonl` 的 **step0 loss 都是 5.158024**，初始状态完全相同。差异来自 warmup：总步数 23 → 69 时 warmup 从 2 步变 7 步，step0 的 lr 从 1e-05 降到 3.33e-06。这属正常现象，不是两次运行串了。
- **判断**：**"加轮数就好"这个假设被否掉**。步数 23 → 69、loss 3.59 → 1.44 降了一半多，但 inner_spanF1 三轮纹丝不动、dev tp 恒为 0。瓶颈不是"训得不够久"，而是"可学的样本太少"：149 类标签摊到 720 句，长尾类平均不到 2 个样本，模型的最优解就是全猜 O。附带暴露一个代码坑：`if val_f1 > best_f1` 在全 0 时 `0 > 0` 永假，只保存了第 1 轮权重。
- **决策**：**不再加 epoch**。切到下一个假设：max_len 128 砍掉了 69.6% 的句子、36.1% 的论元，先验一下"是不是看不全"。

### E04 BERT-4L + Linear（3 epoch，max_len 256）

- **run_name**：`bert4L_linear_256_3e`
- **命令**：`python bert\train.py --data_dir data/myexp --bert_layers 4 --max_len 256 --epochs 3 --decoder linear --run_name bert4L_linear_256_3e`
- **配置**：同 E03，**只改 max_len 128 → 256**（单变量）；69 步
- **结果**：train_loss 3.4296 → 1.4264 → 1.2626；inner_spanF1 三轮全 **0.0000**；`best_epoch=1`；trigger tp=0 fp=0 fn=930；argument tp=0 fp=0 fn=4122；非法序列 0 条；总 1081.4s（364.4 / 358.3 / 358.3）；推理 79.29 ms/句
- **判断**：**"截断"假设被否掉**。放宽到 256 后论元丢失率从 36.1% 降到 3.0%，F1 仍然是 0，说明瓶颈不是"看不全"而是"根本没学会"。另做了 logit 诊断：取 6830 个金标非 O 位置，`O 得分 − 最高非 O 得分` 中位 **+5.54**（p10 +3.96 / p90 +6.70），margin<0 占比 **0.00%** —— 模型对"这里该标非 O"毫无倾向，不是差一点，是完全没到。
- **决策**：**锁定"训练量"为唯一嫌疑**。69 步 vs 老师同配置 486 步，差 7 倍 → 换全量数据，进入阶段 B。

### 阶段 B：processed 5747 句（正式基线，E05 起）

### E05 BERT-4L + Linear（全量 5747，3 epoch）—— 环境校准

- **run_name**：`bert4L_linear_256_full_data`
- **命令**：`python bert\train.py --data_dir data/processed --bert_layers 4 --max_len 256 --epochs 3 --decoder linear --run_name bert4L_linear_256_full_data`
- **配置**：**5173 训练 / 574 内验 / 930 评测**；batch 32；lr 2e-5；head_lr_mult 5.0；seed 42；**486 步**（162 步/轮 × 3，warmup 48）
- **结果**：
  - 过程：train_loss **1.6977 → 0.5560 → 0.4498**；inner_loss 0.6508 → 0.4650 → 0.4229；inner_spanF1 **0.2338 → 0.3942 → 0.4280**（每轮都刷新最优）；`best_epoch=3`
  - dev：trigger **F1=0.7846**（P=0.8272 R=0.7462，tp=694 fp=145 fn=236）；argument **F1=0.3489**（P=0.3105 R=0.3981，tp=1641 fp=3644 fn=2481）；event_exact **F1=0.0599**（tp=53 fp=786 fn=877）；type_macro **0.7781**
  - 930 句中"没抽到触发词"**91 句**（9.8%，阶段 A 是 930/930=100%）
  - 非法 BIO：801/930 含非法序列 **86.1%**（非法开头 1 处、非法转移 3375 处）；训练集对照 88.3%
  - 成本：总 **5022s**（1697 / 1660 / 1664，约 28 分钟/轮）；推理 **79.49 ms/句**；参数 45.7M；峰值显存 0（纯 CPU）
  - n200 子集：trigger 0.7819 / argument 0.3304
- **判断**：**环境校准通过，且几乎完美**。与老师同配置（`bert4L_linear_256`：4 层 / 256 / linear / 3 轮 / 同一份 5747→5173）逐项对照：
  | 指标 | 本机 CPU | 老师 GPU | 差值 |
  |---|---|---|---|
  | trigger F1 | 0.7846 | 0.7793 | +0.5 点 |
  | **argument F1** | **0.3489** | **0.3495** | **−0.06 点** |
  | event_exact F1 | 0.0599 | 0.0535 | +0.6 点 |
  | type_macro | 0.7781 | 0.7617 | +1.6 点 |
  | 非法序列率 | 86.1% | 86.67% | −0.6 点 |
  | inner_spanF1 | 0.4280 | 0.4251 | +0.3 点 |
  | best_epoch | 3 | 3 | 同 |
  | 推理延迟 | 79.49 ms | 7.31 ms | 慢 10.9 倍 |
  | 训练耗时 | 5022s | 259s | 慢 19.4 倍 |
  **所有质量指标差异都落在 930 句评测的统计噪声（±1~2 点）之内**，arg F1 只差 0.0006。说明代码、数据、标签、评测全链路与老师一致，阶段 A 的 F1=0 确系训练量所致，不是 bug。
- **决策**：作为**正式基线**（arg F1 = 0.3489），后续所有变量都与它比。`best_epoch=3` 与老师一致 → 双方都没收敛，加轮仍有空间；但为控制 CPU 时间统一停在 3 轮（与老师预算对齐）。下一步 E06 换骨干（RoBERTa）。

### E06 RoBERTa-4L + Linear（全量 5747，3 epoch，换骨干）

- **run_name**：`roberta4L_linear_256_full_data`
- **命令**：`python bert\train.py --data_dir data/processed --bert_path pretrain_models/roberta-base --bert_layers 4 --max_len 256 --epochs 3 --decoder linear --run_name roberta4L_linear_256_full_data`
- **配置**：与 E05 完全相同，**只改骨干权重**（bert-base-chinese → `iic/nlp_roberta_backbone_base_std` 转换版）；5173 训练 / 574 内验 / 930 评测；486 步
- **结果**：
  - 过程：train_loss 2.0442 → 0.8190 → 0.6799；inner_loss 0.9694 → 0.7130 → 0.6563；inner_spanF1 **0.0019 → 0.2328 → 0.2777**；`best_epoch=3`
  - dev：trigger **0.6990**（P=0.7881 R=0.6280，tp=584 fp=157 fn=346）；argument **0.1927**（P=0.1942 R=0.1912，tp=788 fp=3270 fn=3334）；event_exact **0.0012**（tp=1 fp=740 fn=929）；type_macro **0.5688**
  - 930 句无触发词 **189 句**（20.3%）；非法序列 88.2%（非法开头 12 处、转移 3686 处）
  - 成本：总 4977s（1657/1653/1667）；推理 81.37 ms/句；参数 45.7M
- **判断**：**权重加载没问题，差距出在收敛速度**。先做了权重诊断：roberta ckpt 的 199 个 `bert.*` key 与 BERT 完全对齐（LayerNorm 同为 `gamma/beta` 命名，52 个），`LOAD REPORT` 里那两个 `LayerNorm.weight/bias` 是 RoBERTa 结构自带的冗余 key、不是缺失；两个模型首步 loss 5.0573 vs 5.1130 几乎相同。真正的差异是 `inner_spanF1` 第 1 轮 0.0019 vs BERT 0.2338（差 100 倍），第 3 轮 0.2777 vs 0.4280，且 `best_epoch=3` 仍在上升 → **典型欠训练，不是能力上限低**。推测原因：该权重是手工转换的 backbone 提取版（`cls.predicitions` 拼错、多 2 个顶层 LayerNorm 即转换痕迹），训练目标与 bert-base-chinese 不同，在 2e-5 + 486 步的小预算下适配更慢。
- **决策**：**报告中不得表述为"RoBERTa 劣于 BERT"**，应写"在统一 486 步预算下该骨干不具竞争力（落后 15.6 点），需更长预算才能公平比较"；且 `event_exact` 仅 tp=1 是论元召回过低（19%）导致 5 个论元全中概率≈0.02%，属指标连锁放大，不是独立缺陷。不追加训练预算（成本 84 分钟/3 轮，收益不确定），转入 E07 截断消融。

### E07 BERT-4L + Linear（全量 5747，3 epoch，max_len 128，截断消融）

- **run_name**：`bert4L_linear_128_full_data`
- **命令**：`python bert\train.py --data_dir data\processed --bert_layers 4 --max_len 128 --epochs 3 --decoder linear --run_name bert4L_linear_128_full_data`
- **配置**：与 E05 完全相同，**只改 max_len 256 → 128**；5173 训练 / 574 内验 / 930 评测；486 步
- **结果**：
  - 过程：train_loss 1.8151 → 0.6316 → 0.5055；inner_loss 0.7350 → 0.5168 → 0.4755；inner_spanF1 **0.2364 → 0.3689 → 0.4125**；`best_epoch=3`
  - dev：trigger **0.7971**（P=0.8403 R=0.7581，tp=705 fp=134 fn=225）；argument **0.3253**（P=0.3109 R=0.3411，tp=1406 fp=3116 fn=2716）；event_exact **0.0520**（tp=46 fp=793 fn=884）；type_macro **0.8015**
  - 930 句无触发词 **91 句**（与 256 相同）；非法序列 85.3%
  - 成本：总 **2448s**（838/824/785）；推理 **40.03 ms/句**；参数 45.7M
  - n200：trigger 0.7745 / argument 0.3175
- **判断**：**不是"更短的更差"，而是一笔明确的权衡**。对照 E05（256）：

  | 指标 | 128 | 256 | 差值 |
  |---|---|---|---|
  | trigger F1 | 0.7971 | 0.7846 | **+1.25 点** |
  | argument F1 | 0.3253 | 0.3489 | **−2.36 点** |
  | event_exact F1 | 0.0520 | 0.0599 | −0.79 点 |
  | type_macro | 0.8015 | 0.7781 | **+2.34 点** |
  | 非法序列率 | 85.3% | 86.1% | −0.8 点 |
  | 推理延迟 | 40.03 ms | 79.49 ms | **−49.6%** |
  | 训练耗时 | 2448s | 5022s | **−51.3%** |

  解释：**触发词集中在标题与首句（句首 128 token 内），截断基本伤不到它**，所以 trigger 与 type_macro 反而上升（短序列 + 注意力更集中，前期学得更快）；**论元（金额、日期、股东名）散落全篇且常在文末**，128 截掉 69.6% 的句子尾部、丢失 36.1% 的论元，arg 与 event 直接受损。另注意 epoch1 起步 0.2364 vs 256 的 0.2338 几乎相同 → 差距不在学得慢，而在**信息上限低**。
- **决策**：结论定稿为"**只求事件发现（trigger）→ 128 性价比最优（一半成本换 +1.25 点）；要填全要素或 event_exact → 必须 256**"。随后进入 E08 FinBERT（换骨干，词表同为 21128，严格可比）。

### E08 FinBERT-zh 4L + Linear（全量 5747，3 epoch，换骨干/换领域）

- **run_name**：`finbert4L_linear_256_full_data`
- **命令**：`python bert\train.py --data_dir data\processed --bert_path pretrain_models\finbert-zh --bert_layers 4 --max_len 256 --epochs 3 --decoder linear --run_name finbert4L_linear_256_full_data`
- **配置**：与 E05 完全相同，**只改权重来源**（`bert-base-chinese` → `qolaris/FinBert`）；词表同为 **21128 字级**，切分完全一致 → 严格可比；486 步
- **结果**：
  - 过程：train_loss 1.6068 → 0.4419 → 0.3431；inner_loss 0.5473 → 0.3789 → 0.3368；inner_spanF1 **0.3007 → 0.4694 → 0.5033**；`best_epoch=3`
  - dev：trigger **0.8067**（P=0.8370 R=0.7785，tp=724 fp=141 fn=206）；argument **0.4390**（P=0.3805 R=0.5187，tp=2138 fp=3481 fn=1984）；event_exact **0.0791**（tp=71 fp=794 fn=859）；type_macro **0.8109**
  - 930 句无触发词 **65 句**（BERT 是 91 句，少 26 句）；非法序列 84.3%
  - 成本：总 **4894s**（1633/1638/1622）；推理 **78.50 ms/句**；参数 45.7M
  - n200：trigger 0.7917 / argument 0.4278
- **判断**：**"换领域"的收益显著高于"换架构"**。三个骨干同配置对照：

  | 骨干 | arg F1 | event F1 | 相对 BERT |
  |---|---|---|---|
  | bert-base-chinese（通用） | 0.3489 | 0.0599 | 基准 |
  | iic roberta backbone（通用换架构） | 0.1927 | 0.0012 | **−15.6 点** |
  | **FinBERT-zh（同架构换领域语料）** | **0.4390** | **0.0791** | **+9.0 点** |

  两条硬证据支撑这个提升是真实的、不是"多标换召回"：
  1. **tp 从 1641 → 2138（+30.3%），而 fp 几乎不动（3644 → 3481）** —— 是真找到了更多对的，不是无差别多标。
  2. **第 1 轮起步就领先**：inner_spanF1 0.3007 vs BERT 0.2338（+6.7 点），说明领域预训练把"公告腔"（“拟减持不超过”“持股 5% 以上股东”“质权人”）的表示提前预热好了，不是靠多训几轮追出来的。
  另：召回率从 0.3981 涨到 0.5187（+12 点），精度只从 0.3105 微升到 0.3805 → **它的优势主要在"找得到"，不是"标得准"**，角色混淆（减持方 / 减持比例）这个问题依旧存在。**天花板参照（跨来源，只比高低、不做比例）**：老师 12 层 BERT 的 arg F1 = 0.5630。**不要写成"4 层达到 12 层的 78%"**——两个数来自不同环境，这个比例没有归因价值；本实验的正确参照是"同参数的 BERT-4L 0.3489 → +9.0"。
- **决策**：报告核心结论之一 —— **小预算下的正确换法不是换架构，而是换领域语料**。仍为 `best_epoch=3`（未收敛），若要再涨需加轮；但预算统一停在 3 轮。下一项：出图与汇总表，然后写报告。

### E09 BiLSTM-CRF 本机复现（全量 5747，无预训练，max_len 128，3 epoch）

- **run_name**：`bilstm_crf_full_data`
- **命令**：`python bilstm_crf\train.py --data_dir data\processed --decoder crf --max_len 128 --epochs 3 --emb_dim 128 --hidden 256 --num_layers 1 --lr 1e-3 --run_name bilstm_crf_full_data --device cpu`
- **配置来源**：完全照抄老师原件 `bilstm_crf.json` 的 meta（`.pt` 里的 `epochs=3 / max_len=128 / emb_dim=128 / hidden=256 / lr=0.001`）。**`run_name` 故意不叫 `bilstm_crf`，避免覆盖老师原件**；字表 3269 字（`<PAD>`=0 `<UNK>`=1）。
- **结果**：
  - 过程：train_loss 230.36 → 73.15 → 49.33（CRF 的 NLL 是负对数似然累加，量级与 softmax-CE 不同，**不能和 BERT 的 1.6 比大小**）；inner_spanF1 **0.1388 → 0.4465 → 0.5424**；`best_epoch=3`
  - dev：trigger **0.8057**（P=0.9071 R=0.7247，tp=674 fp=69 fn=256）；argument **0.4609**（P=0.5893 R=0.3785，tp=1560 fp=1087 fn=2562）；event_exact **0.0825**（tp=69 fp=674 fn=861）；type_macro **0.7206**
  - 非法序列 **47.90%**（445 条，其中非法开头 47 处 / 非法转移 619 处）
  - 成本：**300s**（100/99/98）；推理 **3.92 ms/句**；参数 **1.31M**
- **判断：精度复现成功，成本不可跨机比较。** 与老师原件逐项对照：

  | 指标 | 老师原件（2026-11-22） | 本机复现（11-25） | 差值 |
  |---|---|---|---|
  | trigger F1 | 0.8165 | 0.8057 | −1.08 |
  | **argument F1** | 0.4634 | **0.4609** | **−0.25** |
  | event F1 | 0.0885 | 0.0825 | −0.60 |
  | 类型 macro F1 | 0.7306 | 0.7206 | −1.00 |
  | 非法序列占比 | 48.82% | 47.90% | −0.92 |
  | 训练耗时 | 1520.1s | **300s** | **−1220s** |
  | 推理延迟 | 20.56 ms/句 | **3.92 ms/句** | −16.6 |

  精度全部落在 ±1.1 点内（arg 只差 0.25），**说明流水线在“无预训练”这一侧也对齐了**（加上 E05 的 BERT 侧对齐 0.0006，两个方向都已校准）。但耗时差 5 倍、延迟差 5 倍，`peak_gpu_mb` 两边都是 0 → 纯硬件差异，**报告里成本列一律用本机 300s / 3.92ms，不得引用老师那组 1520s**（否则会低估 BiLSTM 的优势）。
- **决策**：这是报告最锋利的对照 —— 同一台机器、同一份数据、同一评测口径：

  | | BiLSTM-CRF | FinBERT-4L | BERT-4L |
  |---|---|---|---|
  | 论元 F1 | **0.4609** | 0.4390 | 0.3489 |
  | 参数 | **1.31M** | 45.7M（35×） | 45.7M（35×） |
  | 训练 | **300s** | 4894s（16×） | 5022s（17×） |
  | 延迟 | **3.92 ms** | 78.50 ms（20×） | 79.49 ms（20×） |
  | 类型 macro | 0.7206 | **0.8109** | 0.7781 |

  两个结论定稿：①**在 CPU + 5173 句这个组合下，从零训练的 BiLSTM-CRF 是性价比最优解**（1/35 参数、1/16 时间、1/20 延迟，论元 F1 还高 2.2 点）；②**它的短板在事件类型判别**（type_macro 0.7206，比 FinBERT 低 9 点），P/R 性格也相反：BiLSTM 是**高精低召**（P .589 / R .379），FinBERT 是**低精高召**（P .381 / R .519），两者互补而非替代。
  另记：CRF 只约束**标签转移**，不约束**首标签**，所以仍有 47.9% 非法（其中 47 处是句子开头直接 `I-`）；想归零需要硬约束。

### E10 BERT-4L + CRF 解码（全量 5747，3 epoch）—— 解码器维度对照

- **run_name**：`bert4L_crf_256_full_data`
- **命令**：`python bert\train.py --data_dir data\processed --bert_layers 4 --max_len 256 --epochs 3 --decoder crf --run_name bert4L_crf_256_full_data`
- **配置**：与 E05 完全相同（5173 训练 / 574 内验 / 930 评测；486 步；batch 32；lr 2e-5；head 5×；seed 42；45.7M；4 层；256），**只改 `--decoder linear → crf`**
- **结果**：
  - 过程：train_loss **259.8885 → 84.4934 → 67.1040**（CRF 是序列 NLL 累加，量级与 softmax-CE 的 1.7 完全不同，**不可比大小**）；inner_loss 97.7018 → 67.0240 → 61.8340；inner_spanF1 **0.2385 → 0.4255 → 0.4604**；dev_spanF1 0.2445 → 0.4220 → 0.4658；`best_epoch=3`
  - dev：trigger **0.7893**（P .8390 / R .7452，tp=693 fp=133 fn=237）；argument **0.3840**（P .3537 / R .4199，tp=1731 fp=3163 fn=2391）；event_exact **0.0672**（tp=59 fp=767 fn=871）；type_macro **0.7569**
  - 930 句无触发词 **104 句**（E05 是 91 句）
  - 非法 BIO：787/930 条 **84.62%**（非法开头 2 处 / 非法转移 2911 处）；训练集对照 4476 条 86.5%
  - 成本：**5669s**（1898 / 1886 / 1885）；推理 **84.49 ms/句**；参数 45.7M
  - n200：trigger 0.7914 / argument 0.3541
- **判断：精度赢了 3.5 分，合法性一分没赢。**
  | 指标 | E10 +CRF | E05 +Linear | 差 |
  |---|---|---|---|
  | 触发词 F1 | 0.7893 | 0.7846 | +0.47 |
  | **论元 F1** | **0.3840** | 0.3489 | **+3.51** |
  | 事件 F1 | 0.0672 | 0.0599 | +0.73 |
  | 类型 macro | 0.7569 | 0.7781 | **−2.12** |
  | **非法序列率** | **84.62%** | 86.13% | **−1.5（几乎没动）** |
  | 训练耗时 | 5669s | 5022s | +12.9% |
  | 推理延迟 | 84.49ms | 79.49ms | +6.3% |

  **为什么 CRF 压不住非法**（本轮最重要的因果链）：训练集自己就有 **4476/5173 = 86.5%** 的序列非法（重叠论元投影到 BIO 的固有冲突），模型输出 84.6% 与训练集同分布。CRF 学到的是"这份数据里哪种转移最常见"，**不是 BIO 规则**——在数据里非法的转移也是最优路径，所以软约束只削掉 1.5 点。对照 BiLSTM-CRF 能压到 47.9%，是因为它从零训练、CRF 转移矩阵收敛得更充分（300s 全部用在序列目标上），而 BERT 只有 486 步微调，转移矩阵同样欠训练。
  `type_macro` 下降 2.12 点的原因：转移约束偏好高频路径，把稀有类型往常见类型拉平，而类型判别并不需要转移信息。
- **决策**：**"+3.51 分换 +13% 成本"是值的，但 CRF 买不到合法性**，所以必须接硬约束复评（E10b）。同时记下一条口径：老师 12L 的 CRF 也只把非法从 66.88% 压到 62.47%（−4.4 点），**"CRF 能治非法"这个直觉在两端都不成立**。

### E10b 上者 + 解码期硬约束（0 训练，纯后处理）

- **run_name**：`bert4L_crf_256_full_data_hard`
- **命令**：`python bert\evaluate_hard_constraint.py --ckpt outputs\checkpoints\bert4L_crf_256_full_data.pt --run_name bert4L_crf_256_full_data_hard --soft_json bert4L_crf_256_full_data --device cpu`
- **配置**：复用 E10 权重，**0 训练**；硬约束装载 **10878 个禁止转移对 + 74 个非法起始标签**；dev 930 同口径
- **结果**：
  - trigger **0.8121**（P .8660 / R .7645，tp=711 fp=110 fn=219）
  - argument **0.5286**（P .5781 / R .4869，tp=2007 fp=1465 fn=2115）
  - event_exact **0.1165**（tp=102 fp=719 fn=828）；type_macro 0.7340
  - 非法：**787 句 → 57 句（6.13%）**；非法转移 2911 → 115 处；**非法开头 2 → 0 处**
  - 延迟 80.21 ms/句；n200：trigger 0.7989 / argument 0.5088
- **判断：硬约束的收益与"基线非法率"正相关，本机比老师大 1.9 倍。**
  | 对比项 | 老师 12L（GPU） | 本机 4L（CPU） |
  |---|---|---|
  | 基线非法率 | 62.47% | **84.62%** |
  | 硬约束后非法率 | 7.42% | **6.13%** |
  | 论元 F1 增量 | +7.51（0.5815→0.6566） | **+14.46（0.3840→0.5286）** |
  | 事件 F1 增量 | +4.80 | +4.93 |

  可纠正的非法路径越多，挤出来的分数越多——**84.6% 的基线给了它 14.5 点空间，62.5% 只给了 7.5 点**。这是一条可复用的经验关系。
- **决策**：三条结论定稿。
  1. **CRF 买精度（+3.5 点），硬约束买合法性（+14.5 点、非法 6.1%），两者不是一回事，必须都做**；
  2. **本机 4L CRF+硬约束 = 0.5286，已超过 BiLSTM-CRF（0.4609，+6.77 点）和 FinBERT（0.4390）**，成为本机精度冠军；但仍低于老师 12L linear（0.5630，**跨来源天花板，只比高低不做减法**）→ **4 层的信息上限没被后处理完全补回**；
  3. 选型要分开说：**精度优先且能等 95 分钟 → 4L CRF+硬约束；性价比优先 → BiLSTM-CRF（1/35 参数、1/19 时间）**。

### E12 两段式流水线（检测 → 13 类分类 → 类型条件论元）—— **不做（理由见 §六）**

- **产物名**：脚本里写死，无 `--run_name`。ckpt `outputs\checkpoints\pipe_detector.pt` / `pipe_type.pt` / `pipe_arg_<类型>.pt`（共 16 个模型）；指标 `outputs\metrics\disc\pipe_detector.json` / `pipe_type.json` / `pipeline.json` / `pipeline_oracle_type.json`
- **命令**：`python bert_pipeline\train.py --device cpu --arg_epochs 3 --cls_epochs 2`
- **变量层级**：属于「**任务分解方式**」这一层（范式层），对照对象是 **E05 联合抽取**；**不与 E10（解码器）平级**——CRF 是同一模型内部的输出层细节，两段式是整体流程拆分。
- **可比性声明（报告里必须写）**：`common\models.py` 的 `BertCls` 用 `AutoModel.from_pretrained(bert_path)`，**固定全 12 层、无层数参数**（第 154 行）；只有 13 个论元专家按 `--arg_layers 4` 截到 4 层。所以本实验 = **12 层检测器 + 4 层专家**，与 E05（4 层联合）不是严格单变量，只能作为"范式层"的粗对照。
- **老师参照（GPU，非本机）**：trigger 0.6769（P .8868 / R .5473）/ argument 0.3690 / event 0.0957 / type_macro 0.5619；训练 405.5s；延迟 49.87 ms/句；16 个模型。
- **诊断锚点（比分数更值得盯的数）**：
  - 检测器 `pipe_detector.json` → `dev_detect_full.f1 = 0.774`（P .7969 / R .7523），clean 版 0.779；
  - `pipeline.json` → `meta.diag.n_detect_dropped = **255**`：930 句里 27.4% 被检测器判"无事件"直接丢弃，后两段再准也救不回来；
  - `meta.diag.type_accuracy_on_dev_extract = 0.9452`（类型很准）；
  - `pipeline_oracle_type.json` → arg 0.3699，只比端到端 0.3690 高 **0.09 点** → **瓶颈不在类型，在检测器召回**。
- **判据**：①`dev_detect_full.f1` ≥ 0.77（低于 0.70 说明检测器欠训练，后面全废，可停）；②`n_detect_dropped` ≤ 280；③`argument.f1` 与 E05 的 0.3489 对比。
- **预计**：本机 2~2.5 小时。推算依据：老师 GPU 405.5s × 你 E05 实测的 CPU/GPU 倍率（5022/259 ≈ 19.4 倍）。大头是检测器 32794 条训练句 × 2 轮 × 12 层。省时间可 `--arg_epochs 2`（约省 20 分钟，但与老师口径不一致，需在报告声明）。
- **判断**：预期全线低于联合（老师已如此）。**它的价值不是争第一，而是给选型建议补一条"我拆开试过、更差"的排除证据**，并量化"误差累积"（丢掉 27.4% 的句子）。
