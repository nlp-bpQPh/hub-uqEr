## 结论与方法对比

### 1. 规则法：情绪任务的天然下限

规则 / 关键词的 Macro-F1 只有 **0.10**，几乎等于随机猜（8 类随机基线 ≈ 0.125），且只覆盖 6/8 类。

原因：情绪识别是**语义任务**，情绪词很少以类别名原样出现在文本里——用户说「你怎么能这样」表达的是生气，但句子中并没有「生气」两个字。规则法的命中率因此只有 4.57%，「关心」「伤心」「疑问」三类几乎完全失效。

> 结论：规则法只适合关键词明确、格式固定的场景（公告标题、语气词快筛），面对需要语义理解的开放文本，天花板极低。

### 2. 判别式方法（TF-IDF / RBT3）：情绪任务的性价比之选

- **TF-IDF + SVM 反而最高（0.843）**：字符 1~2gram 对短文本的词汇共现捕捉得很充分，且情绪词与语境的字面关联较强。
- **RBT3 微调（0.817）略低于 TF-IDF**：RBT3 只有 3 层，参数约 40M，表达能力有限；在数据量不大（3.7k）、字面信号够强的任务上，反而不如 30 万维字符 n-gram 的线性模型。

> 结论：任务难度决定方法选择。当信号集中在字面时，简单方法可能更划算；RBT3 的价值在于它比 bert-base 快 3~4 倍，成本却低一个量级。

### 3. 大模型：零样本不够用，微调才能追上

- **Qwen3-0.6B zero-shot 只有 0.33**：0.6B 的小模型零样本在情绪任务上理解力不足，还伴随少量解析失败。
- **LoRA SFT 后跃升到 0.81**，**全量微调到 0.83**：说明指令微调能显著修复小模型的零样本短板，但最终仍略低于 TF-IDF。

> 结论：封闭标签 + 短文本的情绪分类，判别式（TF-IDF / BERT 系）仍是最经济的选择；本地 0.6B 零样本不可用，必须微调或换更大的 API 模型。

### 4. API 大模型（deepseek-v4-flash）

zero-shot 达到 **0.79**，追平训练类方法，但仍有 7 条解析失败（1.68%）。它不占本地显存、冷启动最快，代价是按 token 计费。

> 结论：需要快速冷启动或临时跨领域任务时，API 是首选；高 QPS、强合规场景则应回到本地微调。

### 5. 一句话总结

- 想**最快最省钱** → TF-IDF + SVM（20 秒训练，0.84）
- 想**省本地资源又能上语义** → API 大模型 zero-shot（0.79）
- 想**可控、可私有化部署** → RBT3 微调（0.82，比 bert-base 快 3 倍）
- 想**让本地大模型可用** → LoRA SFT（0.81，成本比全量低一个量级）

任务本身决定方法：情绪短文本字面信号强，简单基线就很高；真正拉开差距的场景，是更长、更需要上下文理解的文本。
